- **顺序发言的预提交入口只给还没轮到的席位（用户确认 2026-09-28，已按此改代码）**：早先的设计稿允许当前发言人直接用「提前写发言（轮到你时公开）」把内容写完交给下一位，实战里表现为**当前用户发言后这个入口仍然挂着**——标签写着「轮到你时公开」，而他已经轮到甚至已经讲完。现在的口径：`actions.actions_for` 只给「不是当前发言人、且还没记进 `speech_passed`」的席位生成「本轮不发言」与「提前写发言」；`engine.speech_done` 在每次轮次结束时把原发言人记进 `speech_passed`（统一表示“本轮已处理”），所以讲完的席位不会再拿回这两个入口、残留旧表单也会被 `validate_command` 拒绝（`speech.speak` 另有 `sid != speaker` 的显式校验）。当前发言人一律在公屏直接发言，再点「结束本次发言」推进顺序。不要改回「当前发言人也能用提前写发言」的旧行为。

**处决幻视＝被动自动生效（用户确认 2026-09-27，已按此改代码）**：幻视不再是处决阶段可声明的白天技能，也不需要玩家点按——当天的处决名单**一定稿**（`engine.enter_execution`，即投票全部结算、洗脑锁名单与安安后果都写完之后）就由 `engine.auto_gaze` 自动结算一次，把「本日处决名单含有／不含魔女」私下发给奈乃香，并用 `uses["gaze_day"]` 记当天已生效；中毒时照旧**必定**收到一条结果，真假由那一次信息骰决定且不告诉她掷骰结果。可用条件按她的奈乃香牌判定：在场且是当前牌、可行动（非傀儡、未失去技能）。`actions.can_day_ability` 与 `day_fake_allowed` 都显式拒绝 gaze，所以真奈乃香和示人奈乃香的穗乃香都不再有这个按钮、也无法伪装；旧存档里已经写下的 gaze 声明仍按原标签显示且不可质疑（`challengeable` 白名单保留 gaze 只为它）。改动的起因：旧实现只在处决阶段留出 5 秒自动推进窗口（阶段进入后按「无人待办」倒计时），实战里根本点不到。

**傀儡机制的口径（本轮修复，代码为准，不要改回旧行为）**：
- **只禁角色特有技能，保留通用行动与被动（用户 2026-09-28 定案）**：`state.can_use_ability`（`no_ability` 且可行动）管白天技能；`night_abilities` 对傀儡只回「魔女刀」（`["knife"] if card["witch"] else []`），13 水由 `water.use` 单独放行（它本来就不看技能表）；`hiro.exit`、`execution.shoot` 按同一口径拒绝，临刑的「收手并确认」照给。**傀儡自身的被动效果一律保留**：艾玛毒素光环（`poison_sources`，只看艾玛牌存活）、米莉亚替死（`millia_substitute`）、汉娜的四人目击名额（`present`）、玛格之爱的免疫、希罗回溯、雪莉绑定与殉情、奈乃香的被动处决幻视（`engine.auto_gaze` 只看 `present(game, "nanoka")`，不再因傀儡化失效）。傀儡化只关「主动发动」，不改这些自动结算。
- **夜间不再需要主人代确认（好牌傀儡）**：没有可用技能时 `resolution.sync_night_confirmations` 会按「本夜无事可做」自动确认；魔女傀儡带刀，照常等主人代开或代确认，不会卡在「没有行动又占着待办」。
- **复活限定当夜**：`meruru.revive` 的入口与引擎校验都要求 `game["half"] == "night"`（`night_review`／`night_results` 都算当夜）。天亮后死讯已公示、下层牌已登场，再撤销会把公开信息悄悄回滚（头像翻回上层牌且不播报，等于泄露「有人被复活」）。
- **主人出局＝傀儡当前牌立即出局（用户 2026-09-28 定案）**：`state.puppet_master_dead` 判定主人已经离场（牌不存在／出局／不再是魔女），`engine.sync_puppet_bonds` 在每条命令收尾与每次阶段推进后把它那张当前牌按 `cause="puppet"`、`unconditional` 出局（走标准 `damage_preview` + `apply_damage`，死亡记录、半天出局、下层登场与公告口径都与别的出局一致），下层牌还在就由原玩家恢复自主操作、没有下层牌就是整席出局。主人只是「不再是自己席位的当前牌」（没有真的离场）时只解除控制、不处死傀儡；同一半天已经出过一张牌的席位受「半天一牌」限制杀不掉时也退化为解除。解除是永久的——主人后来被复活也不会把已经恢复自主的玩家再拉成傀儡。主持人手动开傀儡（`host.state` 的 `puppet`）同样成对打上／清掉 `no_ability`，持久化时一起记，旧存档在 `upgrade_game` 补 `no_ability`。
- **只读旁观包含私信**：`app/views.view` 对 `puppet_spectator` 把全部频道的 `can_send` 关掉、清空频道动作与悬浮框，`api.send_message` 再按牌面兜一道；控制者按该席身份代读代发私信（`GET /messages?as_seat=` 与实时投递都按受控席位身份放行聊天，但不代读系统情报与证物）。
- **未改的部分**：不新增傀儡专属夜聊频道（T01 保留现状）；主持人仍不能用「席位视角代操作」操作傀儡席（服务端按该席生成的动作表为空，主持人用强制推进或状态裁定兜底）。

**夜间结果与证物阶段的复活待办（用户确认，已按此改代码）**：梅露露的复活窗口最后一站是「夜间结果与证物」阶段（`night_results`）——主持人一推进就是天亮，死讯公示、下层牌登场，撤销会把已经公开的信息悄悄回滚。因此本阶段只要「当夜由这张梅露露牌造成、且尚未处理的死亡」还在、本人又没用掉复活，服务端就把她当成**还没做完本阶段行动的席位**：`state.pending_revive` 给出该席、`actions.outstanding_seats` 收她进来、`views.host_tasks` 多一条**阻塞**待办（`kind="revive"`，动作挂在 `host.warn` 上，可顺着它先发30秒警告），她本人也收到「请决定当夜是否复活」的催办横幅。**推进按钮不禁用**（这是唯一一条「标阻塞但不拒绝推进」的玩家行动）：主持人按下推进时，未决定的复活和其它未完成行动一样立刻按超时处理，只是结果记为放弃——`engine.timeout_seat` 在 `night_results` 写 `game["night"]["revive_declined"]`，30秒警告到点同样走这条路；写完之后复活入口与待办一起关闭，本夜不能再反悔。公开横幅照旧只报「仍有玩家未完成行动」，不列席位（复活是私密技能，列席位等于公开魔女身份）。不在 `night_results`（例如预结算、白天）时没有这条待办。
