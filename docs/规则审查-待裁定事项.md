### B1 奈乃香命中率跨处决阶段不清零 · 采纳

- **现象**：`shot_misses` 只在命中时重置，进入处决阶段只清 `execution_ready` / `execution_shots`。若她连开两枪未命中后活过了这次处决，下次进名单时第一枪就是 3/6。
- **可达性**：进名单等于必死，活过处决只有三条路（质疑成功移出名单、玛格的爱免疫处决、希罗回溯撤销整段），需「主动收手 + 被救活」叠加，不是实战漏洞。
- **位置**：`engine.py:343-349`、`1454-1460`、`654-662`。
- **方案**：进入处决阶段时清零 `shot_misses`，去掉「依赖她必死」这个隐式前提。

### B8 `eliminate_seat` 绕过半天下限并写重复死亡记录 · 采纳

- **现象**：质疑失败整席出局时直接置两张牌 `alive=False`，不查 `half_exits`、也不跳过本已出局的牌 → 同一半天出两张牌，并为已出局的牌补写一条 `death`。
- **规则冲突**：规则九.4 要求「两张角色牌立即一起出局」，规则三.5 要求「同一半天最多出局一张牌」。
- **位置**：`resolution.py:501-519`。
- **方案**：跳过已出局的牌；并在玩家规则里写明「质疑失败」是半天约束的唯一例外。

### B9 蕾雅决斗门槛改成真正的半数语义 · 已决

- **现象**：`(n + 1) // 2 if duel else n // 2 + 1`。n=7 时两者都是 4、n=5 时都是 3 → 奇数分母下决斗门槛没有任何降低，而蕾雅宣布即永久失去本技能。
- **位置**：`engine.py:380-384`；表单文案在 `actions.py:922-933`。
- **方案**：决斗门槛改为 `n // 2`（7 人局 3 票），与「降为半数即可通过」的规则文本一致；表单文案同步。

### B10 第三天艾玛按「当前牌」判定 · 已决

- **现象**：第三天艾玛只判 `alive`，可能把未登场的下层牌魔女化；而夜间行动按当前牌生成 → 该玩家当夜没有刀可点，通知里「你的**当前角色**已魔女化」是假话，还泄露了「魔女化的是我另一张隐藏牌」。
- **位置**：`engine.py:166-172` 对比 `206-209`；`actions.py:416-419`。
- **方案**：第三天只有**某人的当前牌是艾玛**时才魔女化；否则按既有分支退到 A、B 中可转化的席位。死了的不用管。日志里「艾玛已出局」的措辞一并改成涵盖「没有以当前牌登场的艾玛」。

### C2 「魔女化命运」状态卡与实际状态脱钩 · 采纳

### C5 主持人「席位视角代操作」被 422 整体拒绝 · 采纳

## 四、设计取向与平衡（非实现缺陷，供单独评估）

这些不是代码与规则不符，而是规则本身留出的空间；要动需要改规则或改数值口径。

1. **艾玛第三天魔女化 + 全场攻击「不能放弃」= 清场级效果**（B10 之后口径）。艾玛被配牌规则强制放在下层：只有她的上层牌出局、她成为当前牌时，第三天才会以最高优先级魔女化；她还在下层未登场时，第三天改由 A、B 中可转化的当前牌接替。她一旦成为当前牌，当夜的全场攻击就是清场级效果，唯一结构性反制是希罗仍有未用的回溯额度（清场会杀到希罗并触发回溯，且「被魔女袭击指到就发目击」会让全场当夜知道艾玛是谁）。额度用尽则当夜被判负。
2. **顺序发言方向编码「魔女化玩家在哪半边」**。系统在顺序/逆序两个环里取让魔女化玩家更早发言的一侧，顺序公开；观察到「逆序」即证明本局存在魔女化玩家并锁定其中半边，与规则三.6「不得获知他人魔女化状态」冲突。设计稿第 277 行明写了这条规则，属有意设计。
3. **目击名单在不考虑中毒时必然包含真凶**。七双名单基础三人（必含技能处理后的显示真凶），汉娜在场时四人为「真凶 + 在场的汉娜 + 随机两人」，余位随机补齐——当事人只能按人数缩小范围（3 人时约 1/3，4 人时约 1/4）。规则第 62 行明写。
4. **双方胜利条件达成难度不对称**。好人需清空命运席位 A、B **以及任何产生过魔女牌的席位**（含第 4 天起魔典转化的），每个席位两张牌都要出局；魔女只需米莉亚与亚里沙两张牌出局，而这两张牌**可以由好人自己处决、质疑失败或亚里沙的对跳规则送掉**。对跳当天没能处决对跳者时亚里沙出局（主持人裁定）尤其容易由一次误判直接终结对局。
5. **没有天数上限 + 交牌条件严格**。局面一旦进入谁也赢不了的僵持（例如玛格的爱长期锁住关键牌），只能靠主持人手动结束。
6. **命运席位恒从「不含艾玛/米莉亚/亚里沙」的 4 席里抽**。`state.py:661-666` 的不合格席位恒为 3 个互不相同，所以 A、B 恒在固定的 4 席池中产生——本身不构成泄露，但收窄了魔女化目标池。
7. **`/api/online` 的头像地址带 QQ 号**（`nk=<QQ>`）。代码注释承认是有意取舍，未列为缺陷。
